> 每条记录三要素：错在哪、为什么错、怎么改对

## 拼写类

### 1. User-Agent 拼写错误
- **日期**：Day 27
- **错误**："Mozila/5.0" 少了个 l
- **正确**："Mozilla/5.0"
- **教训**：复制官方 User-Agent 字符串，不要手打

### 2. CSS 选择器少字母
- **日期**：Day 27
- **错误**：.new li（HTML 里 class 是 
ews）
- **正确**：.news li
- **教训**：选择器要和 HTML 里的 class 名完全对应

### 3. CSV 写入方法少 s
- **日期**：Day 28
- **错误**：writerow(data) 写多行数据
- **正确**：writerows(data)
- **教训**：writerow 写一行，writerows 写多行

## 概念类

### 1. 类 vs 实例
- **日期**：Day 30
- **错误**：fixture 返回 APIClient（类），调用时报 missing positional argument
- **正确**：返回 APIClient()（实例），加括号才是创建对象
- **教训**：类是图纸，实例是按图纸造出来的东西

### 2. fill() 参数写法
- **日期**：Day 32
- **错误**：
ame.fill("#test", "内容") 把选择器当参数传进去了
- **正确**：page.locator("#test").fill("内容") 先定位再填充
- **教训**：fill() 只接收要输入的文字，选择器要用 locator 单独定位

### 3. with 语句理解
- **日期**：Day 32
- **疑问**：with 是干什么的
- **理解**：with = 用完自动关闭，不管成功还是报错都会自动清理资源
- **适用场景**：文件操作、数据库连接、Playwright 浏览器

## 环境类

### 1. playwright 安装命令
- **日期**：Day 32
- **错误**：playwright install chromium（Node.js 命令，没反应）
- **正确**：python -m playwright install chromium（Python 版命令）
- **教训**：Python 版工具要用 python -m 调用

### 2. http 协议导致超时
- **日期**：Day 27
- **错误**：http://httpbin.org 导致 504 超时
- **正确**：https://httpbin.org
- **教训**：优先用 https，http 不稳定容易超时

## 选择器/等待类

### 1. networkidle 导致超时
- **日期**：Day 32
- **错误**：百度页面用 wait_until="networkidle" 一直超时
- **正确**：改用 wait_until="domcontentloaded"
- **教训**：有持续请求的页面不要用 networkidle

### 2. 百度反爬检测
- **日期**：Day 32
- **错误**：无头模式被百度检测到，搜索框 hidden
- **解决**：加 rgs=['--disable-blink-features=AutomationControlled']
- **教训**：学习阶段不要和反爬硬刚，换简单网站或用本地 HTML
